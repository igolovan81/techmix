# jOOQ Data-Access Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a new `data-access/` category (sibling to `noSQL/`, `template-engines/`, etc.) containing `data-access/jooq/spring-demo` — a Spring Boot app demonstrating jOOQ's type-safe SQL DSL over a fresh e-commerce catalog schema: generated code, joins/aggregations/window functions, dynamic query building, `MULTISET` nested results, batch operations, and transactions (including a Postgres stored function called through jOOQ).

**Architecture:** One Spring Boot app (`com.testingai.jooq`), package-per-pattern like every other module in this repo (`dsl/`, `joins/`, `search/`, `nested/`, `batch/`, `transactions/`, `util/`, `controller/`). A single `schema.sql` file is the one source of truth for table DDL: Spring Boot bootstraps it against H2 (`MODE=PostgreSQL`) for the default profile (used by `mvn test` and local `spring-boot:run` without Docker) and against real Postgres for the `postgres` profile; jOOQ's `DDLDatabase` codegen parses the same file at `generate-sources` time with no live database connection, so `mvn clean package`/`mvn test` need no Docker. The one Postgres-only piece (a PL/pgSQL stored function, called via `DSL.function(...)`, no generated `Routines`) lives in a separate `postgres-functions.sql` applied only under the `postgres` profile, and its own test uses Testcontainers.

**Tech Stack:** Spring Boot 3.4.4, Java 21, `spring-boot-starter-jooq` (jOOQ 3.19.21, confirmed via `mvn help:evaluate -Dexpression=jooq.version` against this repo's `spring-boot-starter-parent`), PostgreSQL driver + Postgres 16 (Docker), H2 (test/default), Testcontainers 1.20.6 (also confirmed via `help:evaluate`), Lombok, springdoc-openapi, Gatling.

**Spec:** `docs/superpowers/specs/2026-09-03-jooq-demo-design.md`

## Global Constraints

- Java 21, Spring Boot 3.4.4. New parent reactor `data-access/pom.xml` (packaging `pom`), modeled on `noSQL/pom.xml` verbatim (same properties, same shared dependencies, same build-plugin block) — only the `groupId`/`artifactId`/`name`/`description`/`modules` differ, plus this parent's surefire `<excludes>` additionally excludes `**/*IT.java` (noSQL's does not).
- Module artifactId: `jooq-demo`; base package: `com.testingai.jooq`; generated-code package: `com.testingai.jooq.generated` (under `target/generated-sources/jooq`, auto-registered as a compile source root by the `jooq-codegen-maven` plugin — no `build-helper-maven-plugin` needed).
- App port: `8104` (next free slot after `batch-processing/spring-batch`'s `8103`). Postgres (docker compose): `5434`.
- `schema.sql` statements must use `CREATE TABLE IF NOT EXISTS` (not bare `CREATE TABLE`) — `spring.sql.init.mode: always` re-runs this script on every app start, and Postgres (unlike in-memory H2) keeps its data across restarts via the docker compose volume, so a non-idempotent script breaks the second `spring-boot:run`.
- Services return dedicated view/DTO records (e.g. `ProductView`, `CategorySummary`), never generated jOOQ `*Record` types directly from a controller-facing method — generated `Record` classes don't serialize cleanly to JSON via Jackson.
- DSLContext-backed unit tests use Spring Boot's `@JooqTest` slice (transactional, rolled back after each test — no manual cleanup code) against the default H2 profile; `DemoControllerTest` uses `@WebMvcTest` + `MockMvc` + `@MockitoBean` per service (this repo's Spring Boot 3.4 convention — not the deprecated `@MockBean`); `OrderTotalServiceIT` is the one exception, using `@SpringBootTest` + Testcontainers against real Postgres.
- `FailureSimulator` follows the exact shape from `message-brokers/kafka/spring-demo/.../util/FailureSimulator.java` per `.claude/rules/code-review.md` (`FAILURE_RATE = 0.05`, `maybeThrow(String context)`, no `shouldFail()`), applied here for the same reason — a uniform, recognizable failure-injection shape across the repo — even though that rule's text scopes literally to `message-brokers/`.
- `FailureSimulator.maybeThrow` fires unconditionally as the first statement inside `OrderPlacementService.placeOrder`'s transaction, which makes ~5% of calls throw regardless of request validity. Any test that calls `placeOrder` must route through the `placeOrderIgnoringSimulatedFailures` retry helper defined in Task 8 rather than asserting on a single raw call, or it will be flaky.
- If a jOOQ API signature in this plan doesn't match jOOQ 3.19.21 exactly, or `DDLDatabase` fails to parse a `schema.sql` construct (e.g. `GENERATED ALWAYS AS IDENTITY`), or generated code produces "column/table not found" errors at runtime from H2/Postgres case-folding mismatches, consult jOOQ's docs (via `context7`, library `/jooq/jooq`) for the exact current syntax/property keys rather than guessing further — the intent (parse these 5 tables from this SQL file with no live DB; render queries that work against both H2 and Postgres) is authoritative, not the exact XML/API shown here. A concrete first thing to try for a case-folding mismatch: change the `defaultNameCase` codegen property from `as_is` to `lower`.
- Field style matches the rest of the repo: Lombok `@RequiredArgsConstructor` + `private final` on services/injected fields, Java `record` for all DTOs/views/requests (per `.claude/rules/code-review.md`'s modern-Java preference). Exact whitespace in this plan's code blocks is not load-bearing — `spotless-maven-plugin` (wired via `.githooks/pre-commit`) reformats on commit.

- [ ] **Step 4: Create the schema (codegen input + runtime DDL for both profiles)**

Create `data-access/jooq/spring-demo/src/main/resources/db/schema.sql`:

```sql
CREATE TABLE IF NOT EXISTS category (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE IF NOT EXISTS product (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    category_id BIGINT NOT NULL REFERENCES category(id),
    name VARCHAR(200) NOT NULL,
    price DECIMAL(10,2) NOT NULL,
    stock INT NOT NULL
);

CREATE TABLE IF NOT EXISTS customer (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    email VARCHAR(200) NOT NULL UNIQUE
);

CREATE TABLE IF NOT EXISTS orders (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id BIGINT NOT NULL REFERENCES customer(id),
    placed_at TIMESTAMP NOT NULL
);

CREATE TABLE IF NOT EXISTS order_item (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    order_id BIGINT NOT NULL REFERENCES orders(id),
    product_id BIGINT NOT NULL REFERENCES product(id),
    quantity INT NOT NULL,
    unit_price DECIMAL(10,2) NOT NULL
);
```

The table is named `orders`, not `order`, because `ORDER` is a reserved SQL keyword. `GENERATED ALWAYS AS IDENTITY` and `IF NOT EXISTS` are both accepted by H2, Postgres, and jOOQ's `DDLDatabase` parser, keeping this one file portable across all three consumers (H2 test/default profile, Postgres `postgres` profile, jOOQ codegen).

Create `data-access/jooq/spring-demo/src/main/resources/db/postgres-functions.sql`:

```sql
CREATE OR REPLACE FUNCTION calculate_order_total(p_order_id BIGINT)
RETURNS DECIMAL(12,2) AS $$
    SELECT COALESCE(SUM(quantity * unit_price), 0)
    FROM order_item
    WHERE order_id = p_order_id;
$$ LANGUAGE sql;
```

This file is Postgres-only (PL/pgSQL isn't portable to H2) and is **not** fed to `DDLDatabase` codegen — only `schema.sql` is.

Create `data-access/jooq/spring-demo/src/main/java/com/testingai/jooq/dsl/CategoryService.java`:

```java
package com.testingai.jooq.dsl;

import static com.testingai.jooq.generated.Tables.CATEGORY;

import java.util.NoSuchElementException;
import lombok.RequiredArgsConstructor;
import org.jooq.DSLContext;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class CategoryService {

    private final DSLContext ctx;

    public CategoryView create(String name) {
```

```java
import static com.testingai.jooq.generated.Tables.CATEGORY;
import static com.testingai.jooq.generated.Tables.PRODUCT;
import static org.jooq.impl.DSL.avg;
import static org.jooq.impl.DSL.count;
import static org.jooq.impl.DSL.partitionBy;
import static org.jooq.impl.DSL.rank;
import static org.jooq.impl.DSL.sum;

import java.util.List;
import lombok.RequiredArgsConstructor;
import org.jooq.DSLContext;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class CatalogQueryService {

    private final DSLContext ctx;

    public List<ProductWithCategory> listProductsWithCategory() {
        return ctx.select(PRODUCT.ID, PRODUCT.NAME, PRODUCT.PRICE, CATEGORY.NAME)
                .from(PRODUCT)
                .join(CATEGORY).on(PRODUCT.CATEGORY_ID.eq(CATEGORY.ID))
                .orderBy(PRODUCT.ID)
                .fetch(r -> new ProductWithCategory(r.value1(), r.value2(), r.value3(), r.value4()));
    }

    public List<CategorySummary> categorySummary() {
        return ctx.select(CATEGORY.ID, CATEGORY.NAME, count(PRODUCT.ID), sum(PRODUCT.STOCK), avg(PRODUCT.PRICE))
                .from(CATEGORY)
                .leftJoin(PRODUCT).on(PRODUCT.CATEGORY_ID.eq(CATEGORY.ID))
                .groupBy(CATEGORY.ID, CATEGORY.NAME)
                .orderBy(CATEGORY.ID)
                .fetch(r -> new CategorySummary(
                        r.value1(),
                        r.value2(),
                        r.value3(),
                        r.value4() == null ? 0 : r.value4().intValue(),
                        r.value5()));
    }

    public List<RankedProduct> rankProductsByPriceWithinCategory() {
        return ctx.select(
                        PRODUCT.ID,
                        PRODUCT.NAME,
                        PRODUCT.PRICE,
                        PRODUCT.CATEGORY_ID,
                        rank().over(partitionBy(PRODUCT.CATEGORY_ID).orderBy(PRODUCT.PRICE.desc())))
                .from(PRODUCT)
                .orderBy(PRODUCT.CATEGORY_ID, PRODUCT.PRICE.desc())
                .fetch(r -> new RankedProduct(r.value1(), r.value2(), r.value3(), r.value4(), r.value5()));
    }
```

```java
package com.testingai.jooq.search;

import static com.testingai.jooq.generated.Tables.PRODUCT;

import com.testingai.jooq.dsl.ProductView;
import java.util.ArrayList;
import java.util.List;
import lombok.RequiredArgsConstructor;
import org.jooq.Condition;
import org.jooq.DSLContext;
import org.jooq.impl.DSL;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class ProductSearchService {

    private final DSLContext ctx;

    public List<ProductView> search(ProductSearchCriteria criteria) {
        List<Condition> conditions = new ArrayList<>();
        if (criteria.categoryId() != null) {
            conditions.add(PRODUCT.CATEGORY_ID.eq(criteria.categoryId()));
        }
        if (criteria.minPrice() != null) {
            conditions.add(PRODUCT.PRICE.ge(criteria.minPrice()));
        }
        if (criteria.maxPrice() != null) {
            conditions.add(PRODUCT.PRICE.le(criteria.maxPrice()));
        }
        if (Boolean.TRUE.equals(criteria.inStockOnly())) {
            conditions.add(PRODUCT.STOCK.gt(0));
        }
        if (criteria.nameContains() != null && !criteria.nameContains().isBlank()) {
            conditions.add(PRODUCT.NAME.likeIgnoreCase("%" + criteria.nameContains() + "%"));
        }

        return ctx.selectFrom(PRODUCT)
                .where(DSL.and(conditions))
                .orderBy(PRODUCT.ID)
                .fetch(r -> new ProductView(r.getId(), r.getCategoryId(), r.getName(), r.getPrice(), r.getStock()));
    }
}
```

```java
package com.testingai.jooq.transactions;

import static com.testingai.jooq.generated.Tables.ORDERS;
import static com.testingai.jooq.generated.Tables.ORDER_ITEM;
import static com.testingai.jooq.generated.Tables.PRODUCT;

import com.testingai.jooq.util.FailureSimulator;
import java.time.LocalDateTime;
import lombok.RequiredArgsConstructor;
import org.jooq.DSLContext;
import org.jooq.impl.DSL;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class OrderPlacementService {

    private final DSLContext ctx;

    public OrderPlaced placeOrder(PlaceOrderRequest request) {
        return ctx.transactionResult(configuration -> {
            var tx = DSL.using(configuration);

            FailureSimulator.maybeThrow("order-placement");

            LocalDateTime placedAt = LocalDateTime.now();
            Long orderId = tx.insertInto(ORDERS, ORDERS.CUSTOMER_ID, ORDERS.PLACED_AT)
                    .values(request.customerId(), placedAt)
                    .returning(ORDERS.ID)
                    .fetchOne()
                    .getId();

            for (OrderLineRequest line : request.lines()) {
                var product = tx.selectFrom(PRODUCT)
                        .where(PRODUCT.ID.eq(line.productId()))
                        .forUpdate()
                        .fetchOne();

                if (product == null || product.getStock() < line.quantity()) {
                    throw new InsufficientStockException(line.productId());
                }

                tx.update(PRODUCT)
                        .set(PRODUCT.STOCK, product.getStock() - line.quantity())
                        .where(PRODUCT.ID.eq(line.productId()))
                        .execute();

                tx.insertInto(
                                ORDER_ITEM, ORDER_ITEM.ORDER_ID, ORDER_ITEM.PRODUCT_ID, ORDER_ITEM.QUANTITY, ORDER_ITEM.UNIT_PRICE)
                        .values(orderId, line.productId(), line.quantity(), product.getPrice())
                        .execute();
            }

            return new OrderPlaced(orderId, request.customerId(), placedAt);
        });
    }
}
```

# jOOQ Demo

A Spring Boot app demonstrating jOOQ's type-safe SQL DSL over a small e-commerce catalog (`category`, `product`, `customer`, `orders`, `order_item`).

## The schema-as-single-source-of-truth mechanism

`src/main/resources/db/schema.sql` is the *only* place the table shape is defined. It is consumed three ways:

1. Spring Boot runs it against an in-memory H2 database (`MODE=PostgreSQL`) on every `mvn test` and on a plain `mvn spring-boot:run` — no Docker needed.
2. Spring Boot runs it against real Postgres when the `postgres` profile is active.
3. jOOQ's `jooq-codegen-maven` plugin parses it directly (via `org.jooq.meta.extensions.ddl.DDLDatabase`) at `generate-sources` time to produce the typed `com.testingai.jooq.generated` classes every service imports — no live database connection is needed for a build.

The one Postgres-only piece is `db/postgres-functions.sql` (a PL/pgSQL function, `calculate_order_total`), applied only under the `postgres` profile and never fed to codegen — it's called via jOOQ's plain `DSL.function(...)`, not a generated `Routine`.

## Prerequisites

- Java 21, Maven
- Docker (only for the `postgres` profile and the one `OrderTotalServiceIT` test)

| `joins` — joins, aggregation, window functions | `GET /demo/products/with-category`, `GET /demo/categories/summary`, `GET /demo/products/ranked` |
